## 2024-03-27 - Optimizing React-Three-Fiber High-Frequency Loops | **Learning:** In high-frequency React-Three-Fiber `useFrame` loops (like calculating a 50x50 grid physics simulation running 2500 times per frame), redundant internal computations (like invariant math or O(N^2) division) can severely degrade frame rates. Pre-calculating invariants and converting division into multiplication (`1 / x`) provides measurable optimization. | **Action:** Always hoist variables invariant across loops out of the loop body and pre-calculate constants. Convert costly divisions to multiplications using inverse numbers whenever possible inside high-frequency `useFrame` physics loops.
## 2026-10-08 - BST kernel implementation (rotation curves) | **Learning:** The correct screening kernel is g_obs = g_bar / (1 - e^(-sqrt(g_bar/a0))); its deep-MOND limit gives v^4 = G*M*a0 (flat). The old v^2 = GM/r + beta*r formula gives v proportional to sqrt(r) at large r -- it rises without bound and never goes flat. That was a physics bug, not a tuning issue; it shipped in RotationCurves.jsx/FluidFlow.jsx and was fixed 2026-10-08. Edge case: g_bar = 0 yields 0/0 (NaN) -- guard it. | **Action:** Implement exactly: `const x = Math.sqrt(gBar / A0); const gObs = gBar <= 0 ? 0 : gBar / (1 - Math.exp(-x)); const v = Math.sqrt(gObs * r);`. Never use the beta*r wake term. Never use "inverse energy cascade" language -- it belongs to a superseded branch. Keep A0 in one shared constants module (see single-source rule below).
## 2026-10-08 - Three.js Y-junction construction pattern | **Learning:** A Y-junction baryon renders as: central junction sphere + three cylinder prongs at 120 degrees in the XZ plane + three endpoint spheres colored r/g/b (quarks are endpoints, not particles). Cylinders default along +Y; orient via quaternion setFromUnitVectors(+Y, direction). | **Action:** Build each prong as `<mesh position={mid} quaternion={quat}><cylinderGeometry args={[r, r, LEN, 16]} /></mesh>` with mid = dir*(LEN/2) and quat from +Y to dir; endpoints as spheres at dir*LEN. Rotate the whole group slowly for inspection. Label tiers in the info panel per `.jules/physics.md`.
## 2026-10-08 - Single source of physics constants | **Learning:** Stale physics shipped because constants were hardcoded per-component (a0, beta, mass formulas). The framework's numbers change as derivations land (e.g. xi 0.34 -> 0.24 fm; 11 -> 10 parameters; trefoil hadrons killed). Scattered literals made the rot unfixable without a rewrite. | **Action:** NEVER hardcode a0, xi, m_H, rho0, or mass formulas inside components. Import all physics constants from one module (e.g. `src/gthConstants.js`) that cites `.jules/physics.md` tiers in comments. When physics.md updates, the constants module updates with it -- one diff, whole app.
